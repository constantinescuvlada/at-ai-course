embedding.py — backfill the vectors

The rows exist, but their vector columns are still empty (NULL in SQL means "no value"). Add a function to embedding.py that finds those rows and fills the vectors in.

It runs SELECT (read rows) to find them, then UPDATE (change rows) with three freshly computed embeddings per row.

embedding.py — continuedFILE
def updateVector():
    try:
        conn = psycopg2.connect(CONN_INFO)
        conn.autocommit = True
        cur = conn.cursor()

        cur.execute("SELECT id, page, title, context FROM at_data WHERE page_vector IS NULL OR title_vector IS NULL OR context_vector IS NULL")
        rows = cur.fetchall()

        print(f"Updating {len(rows)}")

        for row in rows:
            row_id, page, title, context = row

            page_vec = calcEmbed(page)
            title_vec = calcEmbed(title)
            context_vec = calcEmbed(context)

            cur.execute("UPDATE at_data SET page_vector = %s, title_vector = %s, context_vector = %s WHERE id = %s", (page_vec, title_vec, context_vec, row_id))

            print("Updated!")

    except Exception as e:
        print("Error:", e)
    finally:
        if cur:
            cur.close()
        if conn:
            conn.close()

# MAIN
if __name__ == "__main__":
    updateVector()

Why separate inserting from embedding? Inserting text is instant; embedding takes seconds per row (three model calls each). Splitting them means you can re-embed anytime — say, after switching models — without re-typing any content.
