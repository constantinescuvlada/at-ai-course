Selenium E2E test on a self-hosted runner

So far our pytest suite calls the API directly. A Selenium test goes one step further: it opens a real browser and clicks through the Gradio UI exactly like a user. We run it via GitHub Actions on a self-hosted runner, with Selenoid serving the browsers from Docker.

First extend the project: two new lines in requirements.txt, and add *.mp4 to .gitignore — the test records session videos we don’t want committed.

requirements.txt — addFILE
selenium==4.47.0
pydantic==2.13.4
.gitignore — addFILE
*.mp4
TerminalRUN
# GitHub -> Settings -> Actions -> Runners -> “New self-hosted runner” -> Linux, copy the token
cd runner
export RUNNER_TOKEN="AL24XXYU67ZWQ6WUDIXYIN3KSXXXX"
docker compose up -d
TerminalRUN
cd selenoid
./start-selenoid.sh    # dashboard: http://localhost:8082

cd ../tests
pytest seleniumtest.py::test_open_gradio_app -v

1 · Runner: on GitHub open Settings → Actions → Runners, click New self-hosted runner, select Linux and copy the token into the command on the left (run it inside the local runner/ folder). Refresh the page — the new runner local-docker-runner1 appears in the list.

2 · Selenoid: start-selenoid.sh (in the selenoid/ folder) boots the browser containers — check the dashboard at http://localhost:8082. 3 · Test: from the tests/ folder run test_open_gradio_app from seleniumtest.py — it opens the Gradio app in a Chrome inside Selenoid.
