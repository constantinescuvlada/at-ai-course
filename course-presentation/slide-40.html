Semantic search endpoint

The retrieve half of RAG: find the documents closest in meaning to a question. Query(...) reads a parameter from the URL itself — /at_data/search?query=services arrives as query="services".

The function embeds the question (same calcEmbed as always), then the SQL from the pgvector slide ranks rows by <=> distance.

atassistantapi.py — continuedFILE
@app.get("/at_data/search")
def search_by_context(query: str=Query(...), limit: int = 5):
    if not query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")

    try:
        query_vector = calcEmbed(query)
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("""
            SELECT context, context_vector <=> %s::vector AS distance
            FROM at_data
            WHERE context_vector <=> %s::vector < 0.5
            ORDER BY context_vector <=> %s::vector
            LIMIT %s
        """, (query_vector, query_vector, query_vector, limit))
        rows = cur.fetchall()

        contexts = [row[0] for row in rows]

        return contexts

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()

%s::vector tells Postgres to treat the incoming list of numbers as a vector — without the cast, the comparison won't work. The < 0.5 filter drops rows whose meaning is too far from the question; the result is up to 5 text chunks, nearest first.
