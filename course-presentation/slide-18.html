Module 3 · Database
Why it works

What is pgvector?

A database is a program that stores data in tables — rows and columns, like a spreadsheet — and answers questions about it in a language called SQL ("give me every row where…"). PostgreSQL (or just "Postgres") is one of the most popular free databases in the world; it will hold all of our documents.

The problem: a normal database only matches exact words. Search for "vacation policy" and it will never find the document titled "time off rules" — different words, same meaning. A chatbot needs to search by meaning.

pgvector is a plug-in (an "extension") for Postgres that fixes exactly this. It adds one new column type — vector — so every row can store its text's meaning as 768 numbers (the embedding), plus new operators to compare those numbers:

How meaning-search works

  • 1. Each document row stores its meaning-numbers in a vector(768) column
  • 2. When a question arrives, it is turned into numbers the same way
  • 3. The <=> operator measures how far apart two meaning-vectors are
  • 4. Sort by that distance — the top rows are the closest in meaning, even with zero shared words
-- a normal table... plus a vector column
context         TEXT,           -- the document text
context_vector  vector(768)   -- its meaning, as numbers

-- find the 5 rows closest in meaning to a question
ORDER BY context_vector <=> :question
LIMIT 5;

Everything else stays normal Postgres: same SQL, same tools — the vectors simply live next to the text they describe.

Good to know: an extension is switched on once per database with CREATE EXTENSION (you'll do it in Step 9). Dedicated vector databases exist (Pinecone, Chroma, FAISS), but keeping text and vectors in one familiar database is simpler — and the ankane/pgvector Docker image ships Postgres with the extension pre-installed, which is why Step 8 uses it.
