Эндпоинты чтения: список и получение по id

HTTP-запросы бывают разных видов («методов»): GET читает данные, POST создаёт, PUT обновляет, DELETE удаляет. Начнём с двух GET-эндпоинтов: список всех документов и получение одного по его id.

Строка @app.get(...) — это декоратор: он говорит FastAPI «когда запрашивают этот URL, выполни функцию ниже».

atassistantapi.py — продолжениеFILE
@app.get("/at_data/")
def show_pages():
    try:
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("SELECT id, page, title, context, page_vector, title_vector, context_vector FROM at_data")
        rows = cur.fetchall()
        return [
            {
                "id": row[0], "page": row[1], "title": row[2], "context": row[3],
                "page_vector": row[4], "title_vector": row[5], "context_vector": row[6]
            }
            for row in rows
        ]
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()


@app.get("/at_data/{page_id}")
def get_page_by_id(page_id: int):
    try:
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("""
            SELECT id, page, title, context, page_vector, title_vector, context_vector
            FROM at_data WHERE id = %s
        """, (page_id,))
        row = cur.fetchone()

        if not row:
            raise HTTPException(status_code=404, detail="Record not found")

        return {
            "id": row[0], "page": row[1], "title": row[2], "context": row[3],
            "page_vector": row[4], "title_vector": row[5], "context_vector": row[6]
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()

{page_id} в пути становится аргументом функции: запрос /at_data/7 вызывает её с page_id=7. Всё, что функция возвращает, FastAPI автоматически преобразует в JSON.

try / except / finally вокруг каждого эндпоинта: любой сбой превращается в аккуратную HTTP-ошибку 500 вместо «мёртвого» сервера, а finally гарантирует, что подключение к базе данных будет закрыто в любом случае.
