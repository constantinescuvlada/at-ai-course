Как работает Git — четыре места, где живёт ваш код

На шаге 1 была всего одна команда git clone, но Git будет возвращаться и дальше: на шаге 7 вы настроите .gitignore, а каждый файл, который вы напишете начиная с модуля 4, стоит сохранять. Вся модель Git — это четыре места, где может находиться изменение, и по одной команде, чтобы передвинуть его в следующее:

Рабочая папкафайлы, которые вы правите
→
Индексgit add
→
Локальная историяgit commit
→
GitHub / Bitbucketgit push
  • Рабочая папка — каталог ai-bot-learn/ на вашем диске. Правка файла не затрагивает ничего больше.
  • Индекс (staging area) — короткий список изменений, которые попадут в следующее сохранение. git add добавляет их туда.
  • Локальная история — цепочка коммитов в скрытой папке .git/. Коммит — это один снимок состояния плюс сообщение о том, что изменилось.
  • Удалённый репозиторий — копия на хостинге — GitHub для этого курса, Bitbucket во многих компаниях. git push отправляет ваши коммиты наверх, git pull забирает чужие.
git status              # что изменилось?
git add .               # добавить всё
git commit -m "Add search endpoint"
git push                # отправить на сервер

git log --oneline       # прошлые коммиты
git diff                # незакоммиченные правки
Ничто не сохранено, пока вы не сделали commit, и ничто не доступно другим, пока вы не сделали push. Именно поэтому важен .gitignore (шаг 7): он не пускает venv/ и postgres/ в индекс, и коммит остаётся маленьким и читаемым. Этот курс не требует от вас push, но коммит в конце каждого модуля даёт точку, к которой можно вернуться, когда что-то сломается.
