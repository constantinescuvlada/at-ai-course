Эндпоинт семантического поиска

Половина «retrieve» в RAG: найти документы, ближайшие по смыслу к вопросу. Query(...) читает параметр прямо из URL — /at_data/search?query=services приходит как query="services".

Функция вычисляет эмбеддинг вопроса (тот же calcEmbed, что и всегда), а затем SQL со слайда про pgvector ранжирует строки по расстоянию <=>.

atassistantapi.py — продолжениеFILE
@app.get("/at_data/search")
def search_by_context(query: str=Query(...), limit: int = 5):
    if not query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")

    try:
        query_vector = calcEmbed(query)
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("""
            SELECT context, context_vector <=> %s::vector AS distance
            FROM at_data
            WHERE context_vector <=> %s::vector < 0.5
            ORDER BY context_vector <=> %s::vector
            LIMIT %s
        """, (query_vector, query_vector, query_vector, limit))
        rows = cur.fetchall()

        contexts = [row[0] for row in rows]

        return contexts

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()

%s::vector говорит Postgres трактовать входящий список чисел как вектор — без этого приведения типов сравнение не сработает. Фильтр < 0.5 отбрасывает строки, чей смысл слишком далёк от вопроса; результат — до 5 текстовых фрагментов, ближайшие первыми.
