attest.py — integration tests

A test is code that checks other code automatically. assert means "crash loudly if this isn't true" — so a passing run proves the claims held. Integration tests check whole flows through the running system, catching wiring problems a small "unit" test would miss.

Each test talks to the API over HTTP only — exactly like a real client. Create through the API, check through the API, clean up through the API; the test never opens the database itself. Here's the file's helper and one full test:

attest.pyFILE
import requests

BASE_URL = "http://localhost:8080"

def make_payload(prefix):
    return {
        "page": f"{prefix} Page", "title": f"{prefix} Title",
        "context": f"{prefix} Context",
        "page_vector": [0.1]*10, "title_vector": [0.2]*10,
        "context_vector": [0.3]*10
    }

def test_add_page():
    payload = make_payload("Test")
    response = requests.post(f"{BASE_URL}/at_data/", json=payload)
    assert response.status_code == 201
    new_id = response.json()["id"]

    response = requests.get(f"{BASE_URL}/at_data/{new_id}")
    assert response.status_code == 200
    data = response.json()
    assert data["title"] == payload["title"]

    requests.delete(f"{BASE_URL}/at_data/{new_id}")

This style is called black-box testing: the test only sees what a user of the API sees. If POST, GET and DELETE all agree with each other, the whole chain — API, SQL, database — worked. The real file has six more tests: list, reject-invalid, update, delete, get-by-id, and a 404 for a missing id.

Good tests clean up after themselves — this one deletes its test row at the end (through the API too), so running the suite never pollutes your data.
