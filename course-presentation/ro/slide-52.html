attest.py — teste de integrare

Un test este cod care verifică automat alt cod. assert înseamnă „crapă zgomotos dacă asta nu e adevărat" — deci o rulare trecută dovedește că afirmațiile s-au ținut. Testele de integrare verifică fluxuri întregi prin sistemul care rulează și prind probleme de legătură pe care un „unit" test mic nu le-ar vedea.

Fiecare test vorbește cu API-ul doar prin HTTP — exact ca un client real. Creezi prin API, verifici prin API, cureți prin API; testul nu deschide niciodată baza de date. Iată helper-ul fișierului și un test complet:

attest.pyFILE
import requests

BASE_URL = "http://localhost:8080"

def make_payload(prefix):
    return {
        "page": f"{prefix} Page", "title": f"{prefix} Title",
        "context": f"{prefix} Context",
        "page_vector": [0.1]*10, "title_vector": [0.2]*10,
        "context_vector": [0.3]*10
    }

def test_add_page():
    payload = make_payload("Test")
    response = requests.post(f"{BASE_URL}/at_data/", json=payload)
    assert response.status_code == 201
    new_id = response.json()["id"]

    response = requests.get(f"{BASE_URL}/at_data/{new_id}")
    assert response.status_code == 200
    data = response.json()
    assert data["title"] == payload["title"]

    requests.delete(f"{BASE_URL}/at_data/{new_id}")

Stilul acesta se numește testare black-box: testul vede doar ce vede un utilizator al API-ului. Dacă POST, GET și DELETE sunt de acord între ele, întregul lanț — API, SQL, baza de date — a funcționat. Fișierul real mai are șase teste: listare, respingere-invalid, update, delete, get-by-id și un 404 pentru un id inexistent.

Testele bune curăță după ele — acesta își șterge rândul de test la final (tot prin API), așa că rularea suitei nu îți murdărește niciodată datele.
