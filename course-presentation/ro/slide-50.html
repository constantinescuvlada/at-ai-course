attest.py — teste de integrare

Un test este cod care verifică alt cod în mod automat. assert înseamnă „crapă zgomotos dacă asta nu e adevărat” — deci o rulare reușită dovedește că afirmațiile s-au confirmat. Testele de integrare verifică fluxuri întregi (API + bază de date împreună) și prind probleme de „cablare” pe care un test „unit” mic le-ar rata.

Fiecare test apelează API-ul live cu requests, apoi se uită direct în baza de date pentru a confirma că schimbarea chiar a avut loc. Iată partea de pregătire a fișierului și un test complet:

attest.pyFILE
import requests
import psycopg2

BASE_URL = "http://localhost:8080"
CONN_INFO = "host=localhost port=5433 dbname=at_data_db user=vlada password=abc"

def getDbCon():
    return psycopg2.connect(CONN_INFO)

def fetch_by_id_from_db(page_id):
    with getDbCon() as conn:
        with conn.cursor() as cursor:
            cursor.execute("SELECT page, title, context FROM at_data WHERE id = %s", (page_id,))
            return cursor.fetchone()

def test_add_page():
    print("[INFO] TEST 2: Testing ADD POST /at_data/ ...")
    payload = {
        "page": "Test Page",
        "title": "Test Title",
        "context": "Test Context",
        "page_vector": [0.1]*10,
        "title_vector": [0.2]*10,
        "context_vector": [0.3]*10
    }

    response = requests.post(f"{BASE_URL}/at_data/", json=payload)
    assert response.status_code == 201
    new_id = response.json()["id"]

    db_row = fetch_by_id_from_db(new_id)
    assert db_row == ("Test Page", "Test Title", "Test Context")

    with getDbCon() as conn:
        with conn.cursor() as cursor:
            print("[CLEANUP] deleting test info from database...")
            cursor.execute("DELETE FROM at_data WHERE id = %s", (new_id,))
            conn.commit()
    print("[PASS] Test 2 passed")

with ... as ...: deschide o resursă (conexiune, cursor) și o închide automat la finalul blocului — o rudă mai ordonată a lui try/finally. Fișierul real mai conține încă cinci teste exact ca acesta: listare, respingerea datelor invalide, update, delete, get după id.

Testele bune fac curat după ele — acesta își șterge rândul de test la final, așa că rularea suitei nu vă poluează niciodată datele.
