Endpoint de căutare semantică

Jumătatea retrieve din RAG: găsirea documentelor celor mai apropiate ca sens de o întrebare. Query(...) citește un parametru direct din URL — /at_data/search?query=services ajunge ca query="services".

Funcția calculează embedding-ul întrebării (același calcEmbed ca de obicei), apoi SQL-ul de pe slide-ul despre pgvector ordonează rândurile după distanța <=>.

atassistantapi.py — continuareFILE
@app.get("/at_data/search")
def search_by_context(query: str=Query(...), limit: int = 5):
    if not query.strip():
        raise HTTPException(status_code=400, detail="Query cannot be empty")

    try:
        query_vector = calcEmbed(query)
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("""
            SELECT context, context_vector <=> %s::vector AS distance
            FROM at_data
            WHERE context_vector <=> %s::vector < 0.5
            ORDER BY context_vector <=> %s::vector
            LIMIT %s
        """, (query_vector, query_vector, query_vector, limit))
        rows = cur.fetchall()

        contexts = [row[0] for row in rows]

        return contexts

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()

%s::vector îi spune lui Postgres să trateze lista de numere primită ca pe un vector — fără acest cast, comparația nu funcționează. Filtrul < 0.5 elimină rândurile al căror sens este prea departe de întrebare; rezultatul: până la 5 fragmente de text, cele mai apropiate primele.
