Endpoint-uri de citire: listă & obținere după id

Cererile HTTP vin în mai multe feluri („metode”): GET citește date, POST creează, PUT actualizează, DELETE șterge. Începem cu două endpoint-uri GET: listarea tuturor documentelor și obținerea unuia după id-ul său.

Linia @app.get(...) este un decorator — îi spune lui FastAPI „când este cerut acest URL, rulează funcția de mai jos”.

@app.get("/at_data/")
def show_pages():
    try:
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("SELECT id, page, title, context, page_vector, title_vector, context_vector FROM at_data")
        rows = cur.fetchall()
        return [
            {
                "id": row[0], "page": row[1], "title": row[2], "context": row[3],
                "page_vector": row[4], "title_vector": row[5], "context_vector": row[6]
            }
            for row in rows
        ]
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()


@app.get("/at_data/{page_id}")
def get_page_by_id(page_id: int):
    try:
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("""
            SELECT id, page, title, context, page_vector, title_vector, context_vector
            FROM at_data WHERE id = %s
        """, (page_id,))
        row = cur.fetchone()

        if not row:
            raise HTTPException(status_code=404, detail="Record not found")

        return {
            "id": row[0], "page": row[1], "title": row[2], "context": row[3],
            "page_vector": row[4], "title_vector": row[5], "context_vector": row[6]
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()

{page_id} din cale devine argumentul funcției: cererea /at_data/7 o apelează cu page_id=7. Orice returnează funcția, FastAPI convertește automat în JSON.

try / except / finally din jurul fiecărui endpoint: orice cădere devine o eroare HTTP 500 curată în loc de un server blocat, iar finally garantează că, în ambele cazuri, conexiunea la baza de date este închisă.
