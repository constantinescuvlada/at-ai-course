Read endpoints: list & get-by-id

HTTP requests come in kinds ("methods"): GET reads data, POST creates, PUT updates, DELETE removes. We start with two GET endpoints: list all documents, and fetch one by its id.

The @app.get(...) line is a decorator — it tells FastAPI "when this URL is requested, run the function below".

atassistantapi.py — continuedFILE
@app.get("/at_data/")
def show_pages():
    try:
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("SELECT id, page, title, context, page_vector, title_vector, context_vector FROM at_data")
        rows = cur.fetchall()
        return [
            {
                "id": row[0], "page": row[1], "title": row[2], "context": row[3],
                "page_vector": row[4], "title_vector": row[5], "context_vector": row[6]
            }
            for row in rows
        ]
    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()


@app.get("/at_data/{page_id}")
def get_page_by_id(page_id: int):
    try:
        conn = getDbCon()
        cur = conn.cursor()
        cur.execute("""
            SELECT id, page, title, context, page_vector, title_vector, context_vector
            FROM at_data WHERE id = %s
        """, (page_id,))
        row = cur.fetchone()

        if not row:
            raise HTTPException(status_code=404, detail="Record not found")

        return {
            "id": row[0], "page": row[1], "title": row[2], "context": row[3],
            "page_vector": row[4], "title_vector": row[5], "context_vector": row[6]
        }

    except Exception as e:
        raise HTTPException(status_code=500, detail=str(e))
    finally:
        cur.close()
        conn.close()

{page_id} in the path becomes the function's argument: requesting /at_data/7 calls it with page_id=7. Whatever the function returns, FastAPI converts to JSON automatically.

The try / except / finally around every endpoint: any crash becomes a clean HTTP 500 error instead of a dead server, and finally guarantees the database connection is closed either way.
